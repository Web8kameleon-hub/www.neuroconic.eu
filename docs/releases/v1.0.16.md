# Release v1.0.16

Date: 2026-09-06

## Highlights

- Fixed an accidental removal of the `backend_b` failover service that had
  been merged the previous day (commit `2a4c94d`, "remove backend_b
  duplicate, single-backend topology").
- Restored the two-backend (`backend` + `backend_b`) pool that fronts
  `lightning-spp` and `ollama`, across compose, Nginx, guardrails,
  rolling-update tooling, and docs.
- No feature or behavior change beyond restoring the prior, intended
  topology; this is a corrective/revert release.

## What changed

### Runtime topology

- `docker-compose.yml`: re-added the `backend_b` service definition
  (build, env, healthcheck, `depends_on: lightning-spp, ollama`) and
  restored `web`'s `depends_on: backend_b` health gate.
- `deploy/nginx.conf`: restored `least_conn` load balancing and the second
  `server backend_b:8000` upstream entry in `neurosonic_backend_pool`.

### Guardrails

- `scripts/guardrails/compose.services.txt`: re-added `backend_b` to the
  canonical service list.
- `scripts/guardrails/repo_integrity_guard.py`: re-added `backend_b` to
  `required_services` and `health_required`, so a future removal of the
  service will fail CI instead of passing silently.

### Operational scripts and docs

- `scripts/rolling_update_backends.ps1` / `.sh`: restored the two-backend
  build/up/recreate/health-check loop (4-step flow), keeping the
  nginx-reload-after-recreate fix (`bc55c3a`) that was added afterwards.
- `docs/guides/rolling_update_backends.md`: restored wording describing
  both backends.

## Edge cases covered

- `docker compose config` validity with the restored `backend_b` block.
- Guardrail regression class: the same commit that removed `backend_b`
  also relaxed the guard's required-service list, so the guard passed even
  though the pool was degraded to a single backend. The guard now again
  requires `backend_b` explicitly, closing that silent-pass gap.
- Rolling-update step numbering (`[n/4]`) resynced to the two-backend flow.
- `web` service startup ordering: no longer starts before `backend_b`
  reports healthy.
